# 面试讲解提纲

## 为什么不用纯向量检索

年份和事件名称属于确定性约束。纯向量方案可能把“2025 年”映射到语义接近但年份不符的事件，因此显式年份和专名优先走精确过滤；只有模糊语义问题才进入多路召回。

## RRF 如何工作

不同检索器的原始分数不可直接比较。RRF 只使用各通道排名，按 `weight / (k + rank)` 累加；项目提高精确名称、年份和人物通道权重，让确定性证据优先。

## 如何控制幻觉

- 生成 Prompt 明确限制为所给事件资料。
- API 返回和答案编号一致的 `[E#]` 引用。
- 显式年份无匹配时短路拒答。
- 仅有通用词 LIKE 命中时不视为足够证据。
- Qwen 不可用时根据同一检索证据生成本地模板，而不是调用另一个无来源模型。

## 如何评测

评测集覆盖年份、名称、人物、原因、影响、记忆、语义、比较、追问和无答案问题。检索使用 Hit@5/MRR/Recall@1；生成链路检查引用覆盖和关键事实；性能记录本地检索 P95。当前评测为闭集回归测试，下一步应增加独立人工编写问题和权威来源审核。

## 可以继续优化什么

- 为 100 条事件逐条补充权威来源 URL 和资料版本。
- 增加独立人工测试集、LLM-as-judge 与人工双盲事实审核。
- 使用 Qwen Embedding 与跨编码器重排，比较质量、延迟和成本。
- 公共部署增加 Redis 限流、鉴权、指标监控和调用预算。
